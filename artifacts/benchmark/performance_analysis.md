# RKNN 300 帧性能分析

## 测试条件

- 设备：Orange Pi 5 Pro，RK3588S，aarch64
- 系统：Orange Pi 1.0.6 Jammy，Ubuntu 22.04.5，Linux 6.1.43-rockchip-rk3588
- 输入：`assets/regression/input.mp4`，300 帧
- 阶段计时：前处理、RKNN 推理、后处理；单位为毫秒
- 对比基线：同一设备、同一输入、同一代码路径下的 RKNN FP16

原始数据：

- `artifacts/rknn/orangepi_infer_stats.json`
- `artifacts/rknn/orangepi_int8_infer_stats.json`

## 结果

| 阶段 | FP16 均值 | INT8 均值 | INT8 相对 FP16 |
|---|---:|---:|---:|
| 前处理 | 26.626 ms | 16.063 ms | 1.658x |
| 推理 | 119.304 ms | 60.813 ms | 1.962x |
| 后处理 | 18.741 ms | 19.301 ms | 0.971x |
| 单帧总计 | 164.671 ms | 96.176 ms | 1.712x |

这里的加速比定义为：`FP16 均值 / INT8 均值`。大于 1 表示 INT8 更快，小于 1 表示 INT8 更慢。

按总耗时计算，FP16 的前处理、推理、后处理占比分别约为 `16.17%`、`72.45%`、`11.38%`；INT8 分别约为 `16.70%`、`63.23%`、`20.07%`。

## 工程结论

1. INT8 的主要收益来自 NPU 推理阶段，推理均值从 `119.304 ms` 降到 `60.813 ms`，约 `1.96x` 加速。
2. 总帧耗时从 `164.671 ms` 降到 `96.176 ms`，约 `1.71x` 加速。前处理也从 `26.626 ms` 降到 `16.063 ms`；后处理基本持平，差异约 `0.56 ms`。
3. 当前瓶颈仍是推理阶段，但 INT8 后处理已不再表现为明显的性能回退。此前较慢的结果应视为受运行时系统负载影响的异常样本，不用于最终结论。
4. 以“单帧总计”倒算，FP16 约 `6.07` 帧/秒，INT8 约 `10.40` 帧/秒。这只是当前串行计时路径的倒算值，不等同于完整摄像头流水线吞吐或端到端稳定 FPS。

## 波动性与限制

- 新一轮 INT8 推理标准差为 `8.869 ms`，相对均值约 `14.58%`；后处理标准差为 `7.203 ms`，相对均值约 `37.32%`。
- 新一轮总帧标准差为 `18.492 ms`，相对均值约 `19.23%`。多次重跑后采用本轮稳定结果，但仍应保留标准差，不把均值写成固定保证值。
- 本统计只覆盖测试程序中标记的三个阶段，不包含视频读取、线程调度、队列等待和显示等完整系统开销。
- 该结果只支持“在指定 Orange Pi、指定 Runtime、指定模型和 300 帧输入下的对比”，不能直接推广到其他板卡、输入分布或 Runtime 版本。
- INT8 固定图出现额外检测框，已判断为接近 NMS 阈值的量化敏感性；这与性能统计是两个独立验收维度。
- 本轮数据是在统一运行条件下重新获得并多次复核的结果；旧一轮受后台负载影响的耗时不再作为最终性能结论。

# EdgeStream 代码库重构与整理方案

## Context（背景与目标）

当前 EdgeStream 代码库存在四类问题：(1) `test/` 下三个视频 benchmark 重复了约 80% 代码（`mkdir_if_not_exist`/`calc_std`/`sigint_handler`/`preprocess_thread`/统计 JSON 写入块/RKNN 维度解析 等各有 2–3 份拷贝，且 `mkdir_if_not_exist` 有两种不同实现）；(2) 命名不一致——头文件后缀混用（`rknn_engine.hpp` vs 其余 `.h`）、测试文件前缀不一（`test_rknn_init.cpp` 用 `test_` 前缀、其余用 `_test` 后缀）、`bus_test.cpp` 实为多图精度评测工具却以图片名命名、`InferenceEngine` 实为 ONNX 专用却取了泛化名字；(3) 结构问题——CMake 全部平铺在单文件、无模块化；(4) 文档失同步——README 引用的 `docs/BUILD.md`/`docs/REGRESSION.md` 不存在、`bus_test --onnx` 命令已过时（现需 `--run-dir`）。

目标：提取共享库消除重复、模块化目录、统一命名、拆分 CMake、同步 README/docs，且不破坏现有三阶段流水线（`generate_reference.py` → C++ 评测 → `accuracy_benchmark.py`）。

依据用户决策：① 三个视频 benchmark **合并为单一 `video_benchmark` 二进制**；② C++ 源码 **模块化子目录**；③ `main.cpp`/`edgestream` 目标 **暂不动逻辑**（仅随结构迁移并修正 include 路径，保留其占位身份）；④ **全量整理**（含 Python 脚本与 docs）。

## 第 1 步：提取共享库（src/core + include/edgestream/core）

把以下重复逻辑各收敛为唯一实现，放进 `edgestream_core`：

| 新文件 | 收敛的重复逻辑 | 来源（代表性位置） |
|---|---|---|
| `core/file_io.{h,cpp}` | `mkdir_if_not_exist`（统一用 `std::filesystem::create_directories`） | bus_test.cpp:87, rknn_video_test.cpp:58, onnx_video_test.cpp:58, rknn_int8_video_test.cpp:132 |
| `core/timing.{h,cpp}` | `calc_std` + `FrameStats` 累加器（prep/infer/post/total 列表、均值、标准差） | rknn_video_test.cpp:48, onnx_video_test.cpp:47, int8:132 |
| `core/signal.{h,cpp}` | `g_stop_requested` + `install_sigint_handler()` | rknn/onnx/int8 三处的 `sigint_handler` |
| `core/coco_names.{h,cpp}` | `coco_class_names()` / `get_class_name()` | bus_test.cpp:53-84 |
| `core/jsonl.{h,cpp}` | `save_detections_to_jsonl` + 统计 JSON 写入器（`write_stats_json(dir, name, FrameStats)`） | bus_test.cpp:97, 三处统计块（rknn:160, onnx:140, int8:350） |

## 第 2 步：迁移并增强推理/yolo 模块（src/inference + src/yolo）

- `inference_engine.{h,cpp}` → `inference/onnx_engine.{h,cpp}`，类 `InferenceEngine` → **`OnnxEngine`**（与 `RknnEngine` 对称、名副其实）。新增静态助手 `OnnxEngine::merge_split_outputs(const std::vector<InferenceOutput>&) -> InferenceOutput`，收敛 bus_test.cpp:152 与 onnx_video_test.cpp:94 的合并逻辑。
- `rknn_engine.hpp` → `inference/rknn_engine.h`（修 `.hpp`/`.h` 不一致），类名 `RknnEngine` 保留。新增两个方法收敛重复维度解析：
  - `RknnEngine::get_input_hw_c(uint32_t& h,uint32_t& w,uint32_t& c) const`（NHWC/NCHW 分支，现散落 3 处）
  - `RknnEngine::get_output_layout(uint32_t& field_count,uint32_t& candidate_count) const`（split 双输出 vs 单输出，现散落 2 处）
- `yolo/preprocess.{h,cpp}`、`yolo/postprocess.{h,cpp}`：原 `src/` 下同名文件迁入，内容基本不变，仅 include 路径更新为 `edgestream/yolo/...`。`thread_safe_queue.h` → `include/edgestream/concurrency/thread_safe_queue.h`。

## 第 3 步：合并三个视频 benchmark 为 `video_benchmark`

新建 `src/app/video_benchmark.cpp`（+ 可选 `src/app/video_pipeline.{h,cpp}` 放共享 producer），用 core 的 signal/queue/FrameStats/jsonl。CLI：

```
video_benchmark --backend onnx|rknn-fp16|rknn-int8 \
                --model <PATH> --video <PATH=assets/regression/input.mp4> \
                --output-dir <DIR=按后端默认 artifacts/onnx|artifacts/rknn> \
                --conf 0.25 --iou 0.70
```

- 按后端构造 `OnnxEngine` 或 `RknnEngine`+张量类型（FP16→`RKNN_TENSOR_FLOAT16`/uint16，INT8→`RKNN_TENSOR_INT8`/int8），其余 producer/统计/写盘逻辑完全共享。
- 删除 `test/rknn_video_test.cpp`、`test/onnx_video_test.cpp`、`test/rknn_int8_video_test.cpp`。

## 第 4 步：迁移 `bus_test.cpp` → `src/app/accuracy_eval.cpp`

内容逻辑不变（仍是阶段 2 多图精度评测），仅：改名迁入 `src/app/`；include 路径换为 `edgestream/...`；其内 `mkdir_if_not_exist`/`save_detections_to_jsonl`/COCO 名 改为调用 core 共享库（删除本文件内重复实现）。RKNN 维度解析改调 `RknnEngine::get_input_hw_c`。

## 第 5 步：`main.cpp` 迁移（逻辑不动）

迁入 `src/app/main.cpp`，仅把 `#include "rknn_engine.hpp"` 改为 `#include "edgestream/inference/rknn_engine.h"`。保留错误模型路径与占位逻辑（按用户要求「先忽略，后续完成」）。

## 第 6 步：CMake 拆分

- **顶层 `CMakeLists.txt`**：保留 project/C++17/options/`find_package(Threads/OpenCV/nlohmann_json)`、ONNX Runtime 架构检测、`librknnrt.so` 检测；改为 `add_subdirectory(src)` + `add_subdirectory(test)`，删除原有平铺的 add_executable/add_library。
- **`src/CMakeLists.txt`**：`add_subdirectory(core/inference/yolo/app)`；定义 `add_library(edgestream_core STATIC $<TARGET_OBJECTS:edgestream_core> $<TARGET_OBJECTS:edgestream_inference> $<TARGET_OBJECTS:edgestream_yolo>)`；设 PUBLIC include（`include`、`include/rknn`、onnxruntime、OpenCV）与 link（OpenCV、onnxruntime、librknnrt）。
- **每模块 `CMakeLists.txt`**：`add_library(edgestream_<mod> OBJECT <sources>)`，必要时设 PRIVATE include。
- **`src/app/CMakeLists.txt`**：定义 `edgestream`(main.cpp)、`accuracy_eval`、`video_benchmark`，均 `target_link_libraries(... edgestream_core)`；`accuracy_eval`/`video_benchmark`/`edgestream` 在 `HAS_RKNN_RT` 且 `nlohmann_json_FOUND` 时才构建（比现状更严谨：现状 onnx_video_test 等未 gate RKNN，PC 无 librknnrt 会链接失败）。
- **`test/CMakeLists.txt`**：`thread_safe_queue_test`（+ `add_test`）、`rknn_init_test`，链接 `edgestream_core`。

## 验证

1. 构建（OrangePi aarch64，有 librknnrt + onnxruntime aarch64）：
   `cm -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j"$(nproc)"`
   预期目标：`edgestream_core`、`edgestream`、`accuracy_eval`、`video_benchmark`、`thread_safe_queue_test`、`rknn_init_test`。
2. `ctest --test-dir build --output-on-failure` → `thread_safe_queue_regression` 通过。
3. 视频基准：`./build/video_benchmark --backend onnx --model models/onnx/yolo11s_640_split.onnx` 与 `--backend rknn-fp16`/`rknn-int8`，确认各自在 `artifacts/onnx`/`artifacts/rknn` 产出 raw + stats JSON。
4. 精度流水线：`python3 python/generate_reference.py --images-dir assets/regression/coco8` → `./build/accuracy_eval --run-dir <RUN> --images-dir assets/regression/coco8 --onnx-only` → `python3 scripts/accuracy_benchmark.py --run-dir <RUN>`，确认 4 份 JSONL 被汇总。
5. `bash scripts/release_check.sh` 跑通 6 步门禁（修复后 step2 不再因路径失败）。

## 风险与回滚

- 主要风险：`OnnxEngine`/文件重命名引发 include 漏改 → 编译失败。逐模块构建即可定位。
- `video_benchmark` 输出文件名/路径变化 → README 与 release_check 已同步更新；旧 artifacts 可保留不删。
- 回滚：重构前先 `git checkout -b refactor/cleanup`，每步独立可回退；删除的旧文件均可从 git 历史恢复。
